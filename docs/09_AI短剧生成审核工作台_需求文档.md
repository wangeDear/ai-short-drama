# AI 短剧分阶段生成与审核工作台需求文档

> 版本：v0.3  
> 日期：2026-08-19  
> 状态：需求优化稿（v0.2 审核工作台已实现；v0.3 文本创作链路待开发，变更记录见 §17）

## 1. 项目背景

现有 AI 短剧生产流程已经能够通过 ComfyUI、H3、MoCha、VACE、图片模型、音频模型和 FFmpeg 完成分镜图片、分段视频、配音、环境音与成片生成，但目前主要依赖脚本、目录和生成工具界面进行管理，存在以下问题：

- 用户无法在统一界面查看项目、分镜、提示词和生成结果；
- 一个生成任务运行时，不方便切换和管理其他项目；
- 分镜图片、音频和视频缺少明确的审核状态；
- 单段重做容易覆盖旧版本，缺少版本对比；
- ComfyUI 工作流、模型参数和输出文件之间缺少业务层关联；
- 远程服务器、任务队列、生成错误和耗时对用户不透明；
- 成片生成前缺少统一的逐镜验收流程。

因此，需要把现有轻量审核工作台升级为“从创意文本到成片”的分阶段创作与生产系统：系统负责生成可编辑草稿，人负责在高成本或不可逆节点前做判断，ComfyUI 等执行器负责媒体生成。

## 2. 产品定位

工作台是 AI 短剧生产的“创作控制面”，不直接实现图片、视频和音频模型，但负责调用文本模型把创意转换为结构化生产资料。

- 工作台负责：创意理解、剧本与分镜规划、提示词生成、项目管理、任务调度、审核、版本、日志和成片管理；
- 文本模型负责：创意扩写、剧本结构化、角色/场景/道具提取、分镜与提示词草稿；
- ComfyUI/H3/MoCha/VACE 等负责：具体媒体生成；
- FFmpeg 负责：音视频处理与最终合成；
- 本地或远程 GPU 服务器负责：执行生成任务。

支持三种入口：

1. **创意模式**：输入一段自然语言描述，由系统生成剧本和完整生产资料；
2. **剧本模式**：导入已有剧本，从生产设定提取和分镜规划开始；
3. **分镜模式**：导入已有镜表和素材，直接进入审核与生成。

默认核心流程：

```text
输入创意描述/导入剧本
→ AI 生成故事方案与剧本 → 人工审核剧本（卡点 A）
→ AI 提取角色、场景、道具并生成分镜与结构化提示词
→ 人工审核生产设定、分镜和提示词（卡点 B）
→ 生成角色/场景参考图和分镜图片 → 人工批准图片（卡点 C）
→ 自动或手动批量提交分段视频
→ 预览分段视频，人工逐镜采用最终版本（卡点 D）
→ 对问题镜头局部修改、重做和版本对比
→ 全部分镜通过后合成、预览并验收成片
```

“人工批量提交任务”和“最终导出”是操作，不单独算创意审核卡点。用户可开启“审核通过后自动继续”，但系统不得越过 A～D 中已启用的卡点。

## 3. 产品目标

### 3.1 v0.3 目标

1. 在网页中集中管理多个短剧项目；
2. 在生成任务运行期间自由切换项目，不影响后台任务；
3. 展示每个分镜的图片、提示词、音频、视频和状态；
4. 支持分镜图片批准后生成分段视频；
5. 支持对单个分镜修改参数并重新生成；
6. 保存全部历史版本并进行新旧对比；
7. 对接本地、WSL 或远程 ComfyUI；
8. 所有分镜通过后触发成片合成；
9. 工作台重启后能够恢复项目和任务状态；
10. 输入一段创意描述即可生成可编辑的故事方案、剧本、生产设定、分镜和差异化提示词；
11. 生成图片/视频时可直接选择模型，所选模型可追溯（v0.2 新增）；
12. 关键节点采用可持久化人工卡点，刷新、重启或切换项目后可继续；
13. 修改上游内容时只将真正依赖它的下游产物标记为过期，旧版本仍可查看和恢复；
14. 批量生成前展示预计镜头数、图片/视频任务数和预计 GPU 工作量。

### 3.2 非目标

v0.3 暂不实现：

- 多租户和复杂权限系统；
- 在线支付与调用计费；
- 专业非线性时间线编辑器；
- 无人工确认的一键全自动成片；
- 自动选择最优模型；
- LocalMiniDrama 的大规模魔改；
- 云端发布、社交平台投稿；
- 面向公网的高并发部署。

## 4. 用户与使用场景

v0.3 仍以单用户为主，用户同时承担导演、审核者和任务管理员角色。

典型场景：

1. 用户输入“一个人在沙漠中用太阳能板给手机充电”的简短描述，并补充时长、画幅和写实风格；
2. 系统生成故事方案和剧本，用户修改情节、台词和结尾后批准；
3. 系统提取并锁定角色、服装、场景和关键道具，生成镜表与图片/视频提示词；
4. 用户逐镜检查构图、动作、连续性和风险提示，批准后批量生成分镜图片；
5. 用户批准部分分镜图片并批量或自动提交视频生成；
6. H3 正在生成某个项目时，用户切换到另一个项目继续审核；
7. 某个分段效果不好，用户只修改该分段并重新生成；
8. 用户比较 v1、v2、v3，选择最终版本；
9. 所有分段通过后，用户合成并预览最终视频。

## 5. 信息架构

工作台包含以下主要页面：

1. 项目列表与创建向导；
2. 创意与剧本；
3. 生产设定（角色、场景、道具和全局风格）；
4. 分镜与提示词工作台；
5. 分镜图片审核；
6. 分段视频审核；
7. 任务中心；
8. 工作流与生成节点；
9. 成片预览；
10. 系统设置。

项目页顶部固定显示阶段导航、当前卡点、待审核数量、过期数量和后台任务状态，使用户可在项目间切换而不丢失生产上下文。

## 6. 功能需求

### 6.1 项目管理

#### FR-PROJ-001 创建项目

用户可以创建项目，填写：

- 项目名称；
- 简介；
- 画面比例；
- 默认分辨率；
- 默认帧率；
- 默认输出目录；
- 封面图。

#### FR-PROJ-002 导入已有项目

支持从已有项目目录、剧本 Markdown 或约定 JSON 导入：

- 剧本信息；
- 分镜编号和描述；
- 提示词；
- 已有图片、音频和视频；
- 角色参考图；
- 已有生成结果。

#### FR-PROJ-003 项目列表

项目卡片显示：

- 项目名称和封面；
- 更新时间；
- 当前生产阶段；
- 已完成分镜数/总分镜数；
- 正在生成、排队和失败的任务数；
- 最近一次成片状态。

#### FR-PROJ-004 项目切换

- 用户可以随时切换项目；
- 离开项目页面不会取消任务；
- 页面状态与后台执行状态解耦；
- 返回项目时恢复之前的筛选条件和浏览位置。

#### FR-PROJ-005 项目归档与删除

- 项目可以归档和恢复；归档是默认的防误删操作；
- 提供带防护的永久删除（v0.2 新增）：
  - 项目存在排队或运行中任务时拒绝删除；
  - 删除清除项目、分镜、版本、任务、审核、角色与素材记录；
  - 导入引用的源文件（如 outputs/ 已有成片）一律保留；
  - 项目生成的 `projects/{id}/` 目录文件默认保留，勾选确认后方可一并删除；
  - 删除需二次确认。

#### FR-PROJ-006 文本创意/剧本导入（v0.3 调整）

创建向导支持三类输入，并自动识别入口模式：

1. 一段自然语言创意、故事梗概或选题说明；
2. 完整或半结构化剧本；
3. Markdown 镜表或约定 JSON 分镜。

创意模式除原始文本外提供可选高级约束：题材、目标平台、受众、总时长、集数、画幅、语言、写实程度、对白密度、叙事视角、结尾方向、禁用内容和参考风格。未填写项由系统推断，但必须在生成前向用户展示推断结果。

原 v0.2 的三种解析能力继续保留：镜表列名自动映射、结构化剧本识别、纯叙事文本按目标时长聚句。已有镜表的显式时长优先；对白时长估算、默认无对白时长和 seed 派生规则继续有效。

禁止再把同一段描述原样复制到 `image_prompt` 和 `video_prompt`。创意或剧本输入必须先经过结构化生成链路，失败时保留原文并允许人工编辑或重新生成。

### 6.2 文本创作与结构化生成（v0.3 新增）

#### FR-CREATIVE-001 创意简报

系统把用户输入和高级约束保存为 `CreativeBrief` 版本，至少包含：核心创意、题材、受众、平台、总时长、画幅、视觉风格、语言、集数、目标镜头数、对白密度、写实程度、禁用内容和期望结尾。

- 所有推断字段必须可编辑；
- 生成前显示预计场景数、镜头数、图片任务数、视频任务数和粗略 GPU 工作量；
- 修改简报产生新版本，不覆盖旧版本。

#### FR-CREATIVE-002 故事方案与剧本

文本模型分两步输出并允许分别重做：

1. `StoryPlan`：标题、logline、梗概、人物目标、冲突、转折、结尾、情绪曲线和场景列表；
2. `ScriptVersion`：按场组织的动作、对白、旁白、场景目标和预计时长。

输出必须符合 JSON Schema；解析失败时执行有限次数结构修复，仍失败则显示原始输出和错误，不创建残缺的下游实体。用户可逐场编辑、比较版本、批准或退回。

#### FR-CREATIVE-003 生产设定（Production Bible）

系统从已批准剧本提取并生成可锁定的生产设定：

- 角色：稳定外观、年龄、体型、发型、面部特征、服装、声音与禁改特征；
- 场景：地点、时间、天气、空间布局、光线、色彩和可复用背景；
- 道具：外观、尺寸、材质、持有人和跨镜状态；
- 全局风格：画幅、镜头语言、焦段倾向、色彩、颗粒、写实程度和声音原则。

角色、服装、道具状态和场景时间线作为连续性基准；批准后默认锁定。修改某项设定只使引用该项的下游镜头过期。

#### FR-CREATIVE-004 分镜与结构化提示词

系统根据已批准剧本和生产设定生成 `ShotPlan`，每镜至少包含：

- 场次与镜号、叙事目的、时长；
- 景别、机位、构图、镜头运动；
- 主体、动作、表情、对白/旁白；
- 场景、服装、道具状态和与前后镜的连续性；
- 风险标签和建议生成路径。

每镜生成独立的 `PromptPackage`：

- 图片提示词：身份/资产引用、画面瞬间、构图、环境、光线、镜头、风格和负面约束；
- 视频提示词：输入帧/参考资产、主体动作、物体交互、相机运动、时间节奏、首尾帧约束和负面约束；
- 声音提示词：对白/旁白、说话方式、环境音和音乐建议；
- 生成元数据：所需参考图、建议模型/工作流、风险等级、模板版本。

界面同时提供结构化字段编辑和最终拼装文本预览。修改某个字段后重新拼装，不要求用户手工维护整段六段式提示词。

#### FR-CREATIVE-005 风险识别与生成建议

系统对以下高风险镜头显式标记：手与物体接触、多人肢体交互、复杂工具操作、可读文字/手机界面、物体凭空出现或消失、长距离连续动作、口型同步和明显状态变化。

风险标签只用于推荐工作流与提醒，不替用户自动决定模型。高风险镜头可建议参考视频、姿态/深度控制、首尾帧、局部重绘或拆分为多个短镜头；用户保留覆盖权。

### 6.3 分镜管理

#### FR-SHOT-001 分镜列表

支持卡片和紧凑列表两种视图，并可按以下条件筛选：

- 状态；
- 角色；
- 场景；
- 模型；
- 是否失败；
- 是否需要修改。

#### FR-SHOT-002 分镜卡片

每张卡片显示：

- 分镜编号、标题和时长；
- 分镜图片；
- 正向提示词；
- 负向提示词；
- 角色、场景和道具参考图；
- 配音和环境音；
- 当前视频；
- 当前状态；
- 模型、工作流、Seed 和版本号；
- 生成耗时与错误信息；
- 审核备注。

#### FR-SHOT-003 编辑分镜

支持编辑：

- 画面描述；
- 正向和负向提示词；
- 时长；
- 参考图；
- 模型和工作流；
- Seed；
- 分辨率、帧率和生成参数；
- 配音文本；
- 环境音描述。

修改后不立即覆盖旧版本，应形成新的待生成配置。

#### FR-SHOT-004 分镜审核

支持以下审核动作：

- 批准图片；
- 退回修改；
- 批准音频；
- 批准视频；
- 标记需要修改；
- 填写备注；
- 选择最终采用版本。

#### FR-SHOT-005 批量操作

支持批量：

- 批准分镜图片；
- 提交视频生成；
- 重试失败任务；
- 更换工作流；
- 导出审核清单。

### 6.4 素材预览

#### FR-ASSET-001 图片预览

- 支持放大、缩放和全屏；
- 支持查看参考图和生成图；
- 支持并排对比；
- 显示文件名、尺寸和生成参数。

#### FR-ASSET-002 音频试听

- 支持试听配音、环境音和混合音轨；
- 显示时长；
- 支持从头播放和暂停；
- 支持重新生成或替换文件。

#### FR-ASSET-003 视频预览

- 支持网页内播放；
- 支持循环播放；
- 支持静音；
- 支持查看时长、分辨率、帧率；
- 支持原版与新版同步/并排播放；
- 支持下载或打开文件所在目录。

### 6.5 任务系统

#### FR-JOB-001 任务类型

任务至少包括：

- 图片生成；
- 视频生成；
- 配音生成；
- 环境音生成；
- 局部修复；
- 视频分析与抽帧；
- 音视频合成；
- 最终成片导出。

#### FR-JOB-002 任务状态

统一状态如下：

```text
draft          草稿
waiting_review 等待审核
approved       已批准
queued         排队中
running        生成中
reviewing      等待结果审核
succeeded      生成完成
accepted       已通过
revision       需要修改
failed         失败
cancelled      已取消
```

#### FR-JOB-003 后台运行

- 任务由后台 Worker 执行；
- 关闭或刷新浏览器不影响任务；
- 切换项目不影响任务；
- 任务开始后持续记录进度；
- 工作台重启后重新同步 ComfyUI 队列和历史记录。

#### FR-JOB-004 任务操作

支持：

- 提交；
- 调整排队优先级；
- 取消未开始任务；
- 请求取消运行任务；
- 失败重试；
- 使用相同参数重新运行；
- 查看日志；
- 定位输出文件。

#### FR-JOB-005 进度展示

任务显示：

- 当前步骤；
- 已运行时间；
- 预计剩余时间；
- 执行节点；
- 模型和工作流；
- 队列位置；
- 最后一次心跳；
- 错误摘要。

### 6.6 版本管理

#### FR-VER-001 不覆盖旧版本

每次重新生成都创建新版本，例如：

```text
S03 / v1
S03 / v2
S03 / v3
```

#### FR-VER-002 版本快照

每个版本保存：

- 提示词快照；
- 模型和工作流；
- 工作流 JSON 快照或哈希；
- Seed；
- 尺寸、帧率、帧数和时长；
- 输入参考素材；
- 输出素材；
- 生成节点；
- 开始和完成时间；
- 审核结果；
- 用户备注。

#### FR-VER-003 版本对比

- 图片支持并排对比；
- 视频支持并排或切换对比；
- 提示词和参数显示差异；
- 用户可以选择任意版本为最终采用版本；
- 被替换版本仍然保留。

### 6.7 角色与资产

#### FR-CHAR-001 角色档案

角色信息包括：

- 名称；
- 描述；
- 正面、侧面和全身参考图；
- 服装设定；
- 声音设定；
- 默认提示词片段；
- 适用工作流。

#### FR-CHAR-002 公共资产

支持管理：

- 场景参考图；
- 道具参考图；
- 控制视频；
- 姿态或深度视频；
- 音效；
- 字体、字幕和片头片尾素材。

#### FR-CHAR-003 前景保护资产

为后续角色替换和局部修复预留：

- 人物遮罩；
- 手机、工具、手套等保护遮罩；
- 控制视频；
- 原始参考视频；
- 遮罩预览和审核状态。

该功能在 v0.3 中只负责存储和预览，不要求自动完成高质量抠像。

### 6.8 ComfyUI 对接

#### FR-COMFY-001 生成节点

支持登记多个节点：

- 本地 ComfyUI；
- WSL ComfyUI；
- 远程 GPU ComfyUI；
- 其他兼容执行器。

节点信息包括：

- 名称；
- 地址；
- 类型；
- 启用状态；
- GPU 信息；
- 当前队列长度；
- 最近心跳；
- 支持的工作流和模型；
- 可从节点拉取可用模型列表并缓存（v0.2：`/models` 或 `/object_types/CheckpointLoaderSimple`），用于生成时的模型下拉；
- 内置 Mock 节点（离线演示）可在无 ComfyUI 时跑通全流程（真实产出 Pillow 图片/静音 WAV/样例视频）。

#### FR-COMFY-002 工作流模板

支持导入 ComfyUI API workflow JSON，并配置语义参数映射：

```text
业务字段 prompt       → 节点 12.inputs.text
业务字段 negative     → 节点 13.inputs.text
业务字段 seed         → 节点 24.inputs.seed
业务字段 input_image  → 节点 5.inputs.image
业务字段 model_name   → 节点 4.inputs.ckpt_name
业务字段 output_prefix→ 节点 31.inputs.filename_prefix
```

可用业务字段还包括 `width / height / fps / frames / duration / voice_text / ambience_text`。

#### FR-COMFY-003 提交与同步

适配器负责：

- 提交 `/prompt`；
- 查询队列；
- 查询 `/history`；
- 获取输出文件；
- 解析节点错误；
- 更新任务进度；
- 将输出登记到对应分镜版本。

#### FR-COMFY-004 安全边界

- 浏览器不得直接持有 SSH 密码或服务器密钥；
- ComfyUI 地址和凭据仅由后端访问；
- 远程文件操作限制在配置的项目目录；
- 日志中不得输出密码和访问令牌。

### 6.9 模型与工作流路由

v0.3 采用人工选择和默认模板，不做不可见的全自动判断。模型为生成时的一等可选参数（v0.2 已实现）。

建议登记以下工作流类别：

- 关键帧图片生成；
- H3 文生视频；
- H3 图生视频；
- 参考视频/角色一致性；
- MoCha/Wan Animate 角色替换；
- VACE 局部修补；
- 配音；
- 环境音；
- FFmpeg 合成。

每个分镜可以覆盖项目默认工作流。

模型选择规则（v0.2 已实现）：

- 生成分镜图/视频时可直接在模型下拉中选择，留空则使用工作流内置模型；
- 所选模型持久化到分镜参数（`image_model` / `video_model` 分开记忆，下次默认选中），编辑分镜可修改；
- 可选模型列表 = 各节点拉取的模型 ∪ 工作流模板登记的依赖模型（required_models）；
- 所选模型经参数映射 `model_name` 写入 workflow 图（如 CheckpointLoader 的模型输入）；
- 每次生成所用模型记入版本快照（FR-VER-002），版本历史与对比可见；
- 更换模型触发对应环节的状态联动：图片模型 → 图片及下游失效重审；视频模型 → 仅视频配置过期。

### 6.10 成片管理

#### FR-FINAL-001 合成条件

默认只有全部必需分镜均选择最终版本后，才能提交正式合成。

用户可以强制生成预览版，但系统需要提示未通过的分镜。

#### FR-FINAL-002 合成配置

支持配置：

- 分镜顺序；
- 转场；
- 配音；
- 环境音；
- 配乐；
- 字幕；
- 分辨率；
- 帧率；
- 编码参数。

#### FR-FINAL-003 成片版本

最终成片同样需要版本管理，不覆盖旧文件。

### 6.11 生产流水线人工卡点（v0.3 调整）

默认保留四个有明确决策价值的人工卡点。卡点必须保存输入版本、待审输出版本、决定、备注和操作时间；刷新、重启和切换项目后仍停在原位置。每个项目可关闭非必要卡点，但图片批准作为视频生成前置条件不可关闭。

#### FR-GATE-001 图片批准是视频生成的前置条件

- 没有已批准分镜图片的镜，提交视频生成会被服务层拒绝且不产生任务；
- 有图但未批准同样拒绝；
- 已导入视频版本的旧分镜豁免，可直接重做视频。

#### FR-GATE-002 流水线卡点面板

项目概览页展示四个卡点的待办数量、过期数量、阻塞原因，并提供批准、编辑后批准、退回重做和批准后继续四类动作：

```text
A 剧本审核：故事结构、场景、对白、时长和结尾
B 生产包审核：生产设定、镜表、连续性、提示词和风险路径
C 图片审核：角色/场景参考图及逐镜关键帧
D 视频审核：逐镜候选视频对比与最终采用
```

当镜头含对白并需要口型或严格卡时长时，系统在 B 卡点前生成低成本配音草稿，以音频实际时长校准镜头；纯环境声或后期旁白可以延后生成。

图片批准后，用户可选择立即批量提交视频，或启用“C 通过后自动排队”。自动继续只创建已批准镜头的任务，不得作用于未批准或已过期镜头。

#### FR-GATE-003 成片合成条件

沿用 FR-FINAL-001：全部必需分镜选定最终版本才可正式合成；强制预览版需明确标注并提示未通过分镜。

#### FR-GATE-004 审核差异与范围

- 审核页必须显示本版相对上一批准版的字段差异；
- 支持整批批准，也支持只批准部分场景或镜头；
- 批量批准前汇总会被放行的任务数和预计工作量；
- 退回必须可填写结构化原因，供下一次生成使用；
- 已批准版本不能原地修改，修改必须产生新版本并重新进入对应卡点。

## 7. 状态联动规则

系统显式保存实体间依赖关系和内容指纹。上游变化后，下游标记为 `stale`（过期）而不是删除，并说明过期原因；用户可查看或恢复旧分支。

1. 修改创意简报：新建故事分支，原分支及产物保留；
2. 修改某个剧本场景：只使该场景对应的生产设定引用、镜表、提示词和媒体过期；
3. 修改角色/场景/道具设定：只使引用该资产的镜头过期；
4. 修改图片提示词或图片模型：使该镜图片及依赖该图片的视频过期；
5. 修改视频提示词或视频模型：不使已批准图片过期，只使视频配置过期；
6. 更换已批准图片：使依赖该图片的视频过期；
7. 修改对白：使配音、需要口型/卡时长的视频、字幕和成片过期；
8. 修改环境音：只使环境音混合与成片过期；
9. 单分镜重做不影响无依赖关系的其他分镜；
10. 生成失败不删除上一个成功版本；
11. 只有用户明确批准，版本才能成为最终采用版本；
12. 项目页面关闭不改变后台任务状态；
13. 视频生成被“图片已人工批准”卡点拦截（FR-GATE-001）。

## 10. 技术方案

### 10.1 推荐技术栈

- 后端：FastAPI；
- 数据库：SQLite；
- ORM：SQLModel 或 SQLAlchemy；
- 页面：Jinja2 + HTMX；
- 样式：轻量原生 CSS 或小型组件库；
- 后台 Worker：独立进程或基于数据库的轻量队列；
- 视频处理：FFmpeg；
- 文本生成适配器：OpenAI-compatible API，预留 Ollama/本地模型；
- 生成适配器：ComfyUI API；
- 媒体存储：本地文件系统。

v0.3 不建议直接引入复杂 React/Vue 工程，也不建议先魔改 LocalMiniDrama。

### 10.2 模块划分

```text
Web UI
  ├─ 项目与分镜页面
  ├─ 审核与版本页面
  └─ 任务中心

FastAPI
  ├─ Project Service
  ├─ Creative Service
  ├─ Script Service
  ├─ Production Bible Service
  ├─ Prompt Compiler
  ├─ Shot Service
  ├─ Asset Service
  ├─ Review Service
  ├─ Dependency Service
  ├─ Job Service
  └─ Workflow Service

Worker
  ├─ LLM Adapter
  ├─ ComfyUI Adapter
  ├─ FFmpeg Adapter
  ├─ Local Process Adapter
  └─ Remote Executor Adapter
```

### 10.3 任务解耦原则

- Web 请求只负责创建任务，不同步等待生成结束；
- Worker 从数据库领取任务；
- Worker 定期更新进度和心跳；
- UI 优先通过 SSE/WebSocket 获取任务变化，轮询作为断线降级；
- Worker 异常退出后，超时任务可重新进入待确认或重试状态。

### 10.4 分阶段编排与人工中断

- v0.3 先在现有 SQLite 状态机上实现持久化阶段运行，不强制引入新的编排框架；
- 每个阶段是幂等操作：相同输入内容指纹和模板版本可复用结果，重试不会重复创建媒体任务；
- 每次阶段运行保存输入快照、输出快照、文本模型、模板版本、耗时、错误和审核决定；
- 卡点使用 `waiting_review → approved/revision → resumed` 语义，服务重启后可恢复；
- 后续流程复杂度显著上升时，可评估 LangGraph 等支持 checkpoint/interrupt 的编排框架，但业务实体与审核记录不能只保存在框架内部。

### 10.5 文本模型输出约束

- 文本模型通过可替换适配器调用，首期支持 OpenAI-compatible 接口；
- StoryPlan、ScriptVersion、ProductionBible、ShotPlan 和 PromptPackage 分别定义 JSON Schema；
- 提示模板和 schema 均带版本号，并写入生成快照；
- 结构校验失败时最多自动修复两次，禁止用不完整 JSON 静默推进；
- 用户编辑结构化字段后由 Prompt Compiler 确定性拼装最终提示词；
- 每阶段支持“只重做选中项”，避免修改一个镜头时重新生成全项目。

## 11. 非功能需求

### 11.1 可靠性

- 浏览器关闭不丢任务；
- 工作台重启不丢项目和版本；
- 工作台重启后，等待审核的阶段仍可从原卡点继续；
- 任务失败保留错误日志；
- 文本模型返回不合规结构时不得创建半成品下游数据；
- 输出文件写入完成后才能登记为成功；
- 使用文件哈希避免错误引用。

### 11.2 性能

- 100 个分镜以内的项目页面应在 2 秒内完成首屏加载；
- 大图和视频使用缩略图与懒加载；
- 项目切换不得等待后台生成任务结束；
- ComfyUI 执行进度优先使用 WebSocket/SSE 推送；断线后以 2～5 秒轮询降级。

### 11.3 可维护性

- 工作流模板与业务代码分离；
- 模型参数以 JSON 快照保存；
- 生成节点通过适配器扩展；
- 数据库迁移脚本可重复执行；
- 日志包含项目、分镜、版本和任务 ID。

### 11.4 安全性

- 默认只监听本机；
- 远程访问凭据保存在后端环境变量或安全配置中；
- 不在前端和日志中展示密码；
- 对文件路径进行根目录校验，防止越界访问。

## 12. v0.3 验收标准

1. 用户可以创建或导入至少两个项目；
2. 某项目生成视频期间，用户可以切换到另一个项目继续操作；
3. 刷新页面后仍能看到正确的任务状态；
4. 工作台重启后可以恢复项目、分镜、版本和任务记录；
5. 分镜卡片可以展示图片、提示词、音频和视频；
6. 用户可以批准分镜图片并提交视频生成；
7. 用户可以只重做一个分镜；
8. 重做不会覆盖旧版本；
9. 用户可以比较两个视频版本并选择最终版本；
10. 可以查看任务执行节点、耗时和错误日志；
11. ComfyUI 离线时任务保留在队列中；
12. 所有分镜选定最终版本后可以生成预览成片；
13. 项目间的素材、版本和任务不会串联；
14. 粘贴 docs/07 同款镜表可正确创建 12 镜，时长与镜表一致（v0.2）；
15. 无已批准图片的分镜提交视频生成被拒绝且不产生任务，批准后放行；已导入视频的旧分镜豁免（v0.2）；
16. 生成时选择的模型经映射写入 workflow 图，并记入版本快照（v0.2）；
17. 项目永久删除存在任务拦截、二次确认与源文件保留防护（v0.2）。
18. 输入一段不少于 50 字的创意文本，可生成 StoryPlan、结构化剧本、生产设定和可配置数量的分镜；
19. 每镜均有独立的结构化图片提示词和视频提示词，二者不得只是同一描述的复制；
20. 用户可以在 A 卡点编辑剧本，批准后才生成生产设定和镜表；
21. 用户可以在 B 卡点只退回一个场景或镜头，并只重做该范围；
22. C 卡点未批准的镜头不得创建视频任务；已批准镜头可按配置自动或手动排队；
23. 刷新浏览器或重启服务后，A～D 卡点的输入、决定和待办状态可恢复；
24. 修改某角色设定只把引用该角色的镜头标记为过期，其他镜头保持有效；
25. 修改视频提示词不使已批准图片过期；更换已批准图片会使依赖视频过期；
26. 手持工具、手机界面、多人物交互等镜头能得到风险标签和生成路径建议；
27. 批量生成前可看到将创建的图片/视频任务数和预计 GPU 工作量；
28. 文本模型输出不符合 schema 时能够自动修复或明确失败，不静默写入残缺数据；
29. 所有文本生成和媒体生成版本均可追溯到输入、模型、模板/schema、参数和审核决定。

当前回归方式：`python -m unittest workbench.tests.test_workbench`（现有 26 个用例覆盖 v0.2 条目）。v0.3 开发时需为 18～29 新增服务层、状态恢复和端到端测试。

- 单镜重做、版本快照、对比与最终采用；
- FFmpeg 基础合成、成片版本和远程 HTTP 节点登记。

### 13.2 v0.3-A：文本到可审剧本（优先）

- A 卡点持久化、恢复和局部重做；
- 任务数量与 GPU 工作量预估。

该阶段不调用 GPU，也能验证最核心的“文本输入是否能稳定变成可生产剧本”。

### 13.3 v0.3-B：生产设定与结构化分镜

### 13.4 v0.3-C：媒体闭环与精准失效

- 依赖图、内容指纹、`stale` 状态和旧分支恢复；
- ComfyUI WebSocket/SSE 进度；

### 13.5 后续增强

## 14. v0.3 默认决策

为避免第一版范围失控，默认采用以下决定：

- 单用户；
- 本机访问；
- FastAPI + SQLite + Jinja2/HTMX；
- 本地文件系统存储；
- ComfyUI 作为首个生成适配器，另内置 Mock 节点用于离线演示全流程；
- 工作流模板由管理员导入；
- 文本模型首期走 OpenAI-compatible 接口，各阶段可配置模型和模板；
- StoryPlan、ScriptVersion、ProductionBible、ShotPlan 和 PromptPackage 强制结构化输出；
- 模型由用户选择，系统只做可解释的工作流建议，不做不可见的自动路由；
- 所有重做产生新版本；
- 项目归档为防误删默认操作，永久删除为带防护的显式危险操作（v0.2）；
- 创意模式生成剧本和结构化提示词，剧本模式与分镜模式继续兼容已有导入能力；
- 默认启用 A～D 四个卡点；“图片批准后自动提交视频”默认关闭；
- 对白镜在分镜确认前可先生成配音草稿用于锁定时长；
- 上游变化使下游标记过期，不自动删除历史产物；
- 先实现简单网页工作台，不魔改 LocalMiniDrama。

## 16. 调研结论与设计依据

### 16.1 类似项目观察

- [LocalMiniDrama](https://github.com/xuanyustudio/LocalMiniDrama/blob/main/docs/en.md) 已形成“故事生成→剧本编辑→角色/场景/道具→分镜→图片/视频→合成”的完整链路，也支持分镜字段编辑、素材库、异步任务恢复和尾帧衔接。说明阶段化创作和资产优先是成熟方向；本项目应复用这一产品逻辑，但保留现有 FastAPI/ComfyUI 管线，不做大规模魔改。
- [LumenX Studio](https://github.com/alibaba/lumenx) 将小说文本转换为剧本分析、角色定制、分镜绘制和视频合成，其后端也把 LLM、资产、分镜、视频、音频和导出拆成独立模块。说明“生产设定/资产层”不应省略，否则角色和道具一致性难以管理。
- [Story2Video](https://github.com/approximatelylinear/story2video) 将故事拆为包含场景、人物、动作、情绪、对白和时长的结构化场景，再生成相机、光线和运动提示，并提供一致性处理。说明描述、图片提示词和视频提示词必须是不同用途的结构，而不是复制同一段文字。
- [LTX Studio 的 script-to-storyboard 流程](https://ltx.io/studio/platform/ai-movie-maker) 强调先把脚本转为可排序、可改时长的分镜，再进入生成。说明分镜图片不仅是产物，也是低成本的导演决策界面。

### 16.2 技术依据

- [LangGraph Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts) 展示了持久化状态、暂停、审核/编辑/拒绝和恢复的 HITL 语义。v0.3 借用这一状态机思想；首期不强制引入 LangGraph，以免为了四个固定卡点增加框架复杂度。
- [ComfyUI 官方服务端路由](https://docs.comfy.org/development/comfyui-server/comms_routes) 提供 `/prompt`、`/history/{prompt_id}` 和 `/ws`。现有提交与历史同步方向正确，v0.3 应补 WebSocket 实时进度并保留轮询降级。

### 16.3 评估结论

调整后的需求合理，并且比“先生成一堆提示词，再让用户逐条补写”更接近真实生产流程。最关键的优化是：

1. 把入口从“导入镜表”上移到“创意/剧本/镜表三模式”；
2. 在分镜前增加 Production Bible，先锁定角色、场景、道具和风格；
3. 把每镜提示词拆为图片、视频和声音三个结构化包；
4. 将五个操作节点收敛为 A～D 四个有决策价值的审核卡点；
5. 通过依赖图和内容指纹精准失效下游，而不是全项目重做；
6. 保留本地工作台和 ComfyUI 作为执行底座，不直接迁移或魔改其他大型项目。
