## v6 · 2026-08-15 · 三层防御拼接连贯版 ⭐当前生产版本

**解决的问题**：v5 全片固定 12s 节奏拖沓；段间色调漂移；同场景动作切换处内容跳变。

**改动（6 项）**：
1. 节拍化变时长：建立镜 10s / 对白镜 6-8s（时长=台词字数÷4.5字/s+1.5s余量）/ 反应镜 5s；帧数对齐 `%17==5`
2. 光线锚点：全片固定光线描述（4300K 暖金主光左上）逐字拼入每镜 prompt
3. 场景固定 seed：同场景镜头共用 noise_seed，光环境不再漂移
4. 三类转场（写进剧本 `trans_out` 字段）：
   - `cut` 跨场景 → 硬切（ref2va 参考图新镜头）
   - `chain` 同场景连续动作 → **fl2va 帧链接**（提取上镜实际尾帧作 first_frame 续写）+ 0.4s xfade
   - `dissolve` 时空转场 → 1.2s 交叉淡化
5. 两阶段拼接：连续 cut 组 concat demuxer 无损拼块 → 块间逐对双输入 fold 转场
6. 统一调色：成片前全片 `eq=contrast=1.04:saturation=1.06 + colorbalance` 轻暖调拉平

**验证**：第一幕 8 镜 60s 全链路跑通；反应镜(5s)仅 72s、帧链接镜 136s、全幕约 35 分钟。

**产物**：`outputs/c3_act1_final.mp4` + `c3_S01..S08.mp4`

**踩坑记录**：
- ffmpeg 多输入长链 filter_complex（8 输入串 concat/xfade）报 `Error reinitializing filters`，帧数时长均正常仍失败（疑 timebase 中段变化）→ 两阶段方案根治
- xfade offset 必须按视频流帧数（nb_frames/24）计算；ffprobe 容器 duration 混入音频拖尾会虚高导致 offset 超界
- 多脚本共用 status.json 互相覆盖 → 状态文件应带脚本前缀

**遗留**：全片尚未用 v6 重生成；BGM 铺底未做；调色是固定参数（未做向参考镜自动对齐）；未超分。

## v4 · 2026-08-14 · 单段 15s 多镜头叙事（moonpostman_oneshot.py）

**解决的问题**：v3 后拼接点平滑但段内仍不连贯——根因是把"镜头切换"塞进生成段（不可达尾帧导致中途跑飞）。

**改动**：彻底放弃拼接。H3 单段生成 15s/362 帧，prompt 按官方结构写完整分镜脚本（[0-4s][4-8s]...时间戳镜头 + camera + audio）；Qwen 生成 864×480 首帧（与 H3 画布同尺寸，消除首帧 stretch/尾帧 crop 的构图错位）。

**验证**：15.08s 成片零拼接零跳变，441s 生成。

**产物**：`Project022/outputs/moonpostman_oneshot_00001_.mp4`

**结论**：≤15s 的故事单段生成最优；>15s 必须分段——分段时的连贯策略由 v6 的三类转场解决。

## v3 · 2026-08-14 · 帧链接 + xfade（moonpostman.py v3）

**解决的问题**：v2 首尾帧版拼接点仍有可见跳变（模型对尾帧只是"逼近"，两侧画面是两次独立近似）。

**改动**：`ffmpeg -sseof -0.1` 提取上镜**实际生成的尾帧**作下镜 first_frame（拼接点两侧变成对同一帧的两次重建）；段间 0.4s xfade+acrossfade 掩盖残余重建差；不再裁剪。

**验证**：拼接点内容差趋近于零，但**段内运动仍不连贯**（5s 内完成远景→中景属"不可达尾帧"，模型中途跑飞）。

**产物**：`Project022/outputs/moonpostman_chain_final.mp4`

**教训（重要）**：拼接近乎完美也不够——问题本质是把剪辑点藏进扩散过程；镜头切换应该交给剪辑（cut），只有同场景连续动作才值得帧链接。

## v1 · 2026-08-14 · 初版流水线（moonpostman.py）

**内容**：Qwen-Image-Edit-2511(turbo 4步)生成静帧 1024×576 → H3 fl2va 单帧 i2v 5s×3 段 → ffmpeg concat 硬拼。

**踩坑（API 格式与 UI 工作流差异，全部已修复进脚本）**：
1. subgraph UI 工作流不能直接转 API，需按 `definitions.subgraphs[].links` 手工展开

## v7 · 2026-08-16 · 真人漫剧 multishot 全流程（《森林求生·取火篇》）⭐当前生产版本

**解决的问题**：沙雕动画型剧本(旁白驱动+手部操作+精确喜剧节拍)直投视频管线"完全不像样"；调研确认根因=剧本形态与扩散管线错配(HOI崩坏/旁白失控/文字梗失效)。

**改动（动态漫混合架构 → 定稿 04 的落地实现）**：
1. 按场组织：LTX-2.5 multishot I2V，一场 2-4 镜头原生切换（Qwen 写实场首帧锚定）
2. 旁白外挂：edge-tts（YunxiNeural 纪录片男声 +8% 语速）+ 系统音（XiaoyiNeural）+
   合成"叮"音效；**先配音后画面**，场时长=音轨时长+1s（8k+1 对齐）
3. 手部过程镜头改"成品特写+旁白带过"（绕开 HOI 死亡区）
4. 1080p(1920×1088) distilled 8 步；无字幕（NOTEXT 强化）
5. 程序化 BGM 垫底（aevalsrc 合成 bass 脉冲，音量 0.10）
6. **纯视觉视频链路**（去 AV：见踩坑）

**验证**：18 场（10 原始场自动二拆>15.5s 者）全部生成，成片 207s/16M；
multishot 切换/人物一致/写实感经视觉模型抽帧确认。

**产物**：`outputs/forest_fire/fr_final.mp4` + 18 分场 + 19 音轨

**踩坑（重要）**：
- **LTX-2.5 空音频 latent >~300 帧必 NaN**（aac Input contains NaN → SaveVideo 崩）：
  713/470 帧均挂，294 帧曾过。根治=去掉 AV 链路纯视觉生成，音频全后期外挂
- gemma 编码在 CPU（device=cpu）与视频时长无关地占每场 ~2-3 分钟（1080p 大场 625s 中约一半）
- 场>15.5s 自动二拆逻辑：narr 按估时(4.2字/s)均衡分组，shots 按比例分
- edge-tts 偶发 "No audio was received" 重试即可（4 次内必成）

**遗留**：环境音缺失（纯视觉无原生声，BGM 单薄）；dev 25 步画质档未跑（用户选 distilled 1080p）；
5090 上 1080p 场均 ~9 分钟（CPU 编码占半，可优化 Gemma 上 GPU 自动调度）。

## v9 · 2026-08-17 · H3 vlog 竖屏全量版 ⭐当前生产版本【用户验收通过】

**解决的问题**：LTX 版"太假不像真实荒野求生"→ 用户拍板切换 H3 + 自拍 vlog 风格 + 竖屏。

**改动**：
1. 六段式 prompt 首次实战（demo 验证口型"基本能对上"）：speaker (S1) + `[Chinese] \`台词。\``
   + 唇动/闭嘴描述 + soundscape/music 分层 —— H3 原生中文对白可用
2. 镜头语言 vlog 化：自拍广角手臂距/俯拍固定机位/低角度仰拍，去电影感调色
3. 竖屏 544×960（H3 ref2va）；demo 3 镜直接复用为正式镜
4. 系统音走后期 TTS 叠加（XiaoyiNeural+叮），口型镜全用 H3 原生音
5. 全 cut 硬切拼接（concat demuxer 无损）+ 极低 BGM 垫底

**验证**：24/24 镜零黑屏；总时长 180.7s；单镜 168-377s，全量约 1.6h。

**产物**：`outputs/forest_fire/取火篇_vlog竖屏_final.mp4`（59M）+ `vlog_shots/`×24

**经验**：
- 六段式规范是对白质量的关键（此前"含糊"根因确认）；台词结尾必须有句号
- H3 竖屏耗时与横屏相近（544×960 ≈ 864×480 像素量）
- 特效镜（雷劈）prompt 写"sideways/natural-looking jagged bolt"可弱化 AI 感
- compshare start 无 --yes 参数（stop 才有）
